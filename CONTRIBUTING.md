# Contributing

## Running locally

You need Go 1.26 or later and Docker.

```bash
make postgres-up mongo-up clickhouse-up mysql-up  # PostgreSQL on 55434, MongoDB with authentication on 55435, ClickHouse HTTP on 55436, MySQL on 55437
make check                               # go vet, go test -race, golangci-lint (in Docker)
make postgres-down mongo-down clickhouse-down mysql-down
```

Without the databases the source and end-to-end tests are skipped, not failed, so
check the output if a run looks fast (`go test -v ./... | grep SKIP`). The Makefile
sets `MONEY_CHECKS_TEST_PG_DSN`, `MONEY_CHECKS_TEST_MONGO_URI` and
`MONEY_CHECKS_TEST_CLICKHOUSE_URL` for the containers above. The MongoDB tests need
authentication on, because they check that a user who can write is refused. The
ClickHouse tests create users and roles, so the ClickHouse user needs access
management (`CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1`).

```bash
go test ./internal/report -update                 # rewrite the golden reports after an intended change
cd examples/subscriptions && docker compose build && docker compose run --rm money-checks run -c /etc/money-checks/checks.yaml
```

## Where things are

| Path | What |
|---|---|
| `internal/money` | Amounts as int64 minor units; `iso4217.go` is generated by `go run ./internal/money/gen` |
| `internal/config` | `checks.yaml` and its validation |
| `internal/source` | PostgreSQL, MySQL, MongoDB and ClickHouse, and turning values into amounts |
| `internal/check` | Running the checks, totals per currency, samples and masking |
| `internal/report` | Markdown and JSON |
| `internal/serve` | The schedule, metrics, readiness and Slack |
| `examples/subscriptions` | The example shop; `tests.yaml` is what the checks must find, for `money-checks test` |
| `recipes` | Checks to copy, one folder per database, with the data they are tested on |

## Adding a recipe

1. Put the query in `recipes/<database>/<recipe>.sql` (or `.yaml` for a MongoDB
   pipeline), with a comment that says how the bug happens in real systems.
2. Add the check to `checks.yaml` in that folder, with an `expect`.
3. Add rows that break it and, next to them, rows at the edge that must not: zero,
   the end of a window, a partial refund. Rows a recipe judges by age are dated
   from now (see `recipes/README.md`).
4. Add what it must find to `tests.yaml`, a row to the catalog in
   `recipes/README.md`, and run the tests there with Docker.

A recipe reads tables the other recipes read where it can, so the data stays one
small, consistent system.

## Adding a source

1. Implement `source.Source` in `internal/source`, and make `Open` refuse a
   connection that can write, or say why the database itself prevents writes.
2. Return values as one of the `Row` value types, so amounts go through
   `source.Minor` and never through a float.
3. Test against the real database in CI, including a check that tries to write.
4. Add the keys to `internal/config` and `docs/config.md`.

## Pull requests

- One logical change per pull request.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/).
- No floats for money, anywhere. A source must not be able to write.
- `make check` passes with the databases up. Add a line to `CHANGELOG.md`.
